# ADR-0001: 製品ごとに Firebase プロジェクトを分ける

- 状態: 採用済み(既存方針の記録)
- 日付: 2026-11-27

## 背景
BuzzIt / RunWith / ClipIt / ShapeIt / DeckIt / PreDeck / RaiseIt は、それぞれ別の Firebase プロジェクト(別 Auth・別 Firestore・別 Storage)で運用している(`deploy/.firebaserc`、`docs/FIREBASE-SPLIT.md`)。

## 決定
この分割を維持する。新製品(Reelit 等)も専用プロジェクトを作る。製品間で DB・Auth を共有しない。

## 理由
- 顧客データの混在リスクを構造的に避けられる(医療系顧客と一般顧客の分離にも有効)。
- 障害・コスト・権限の影響範囲を製品単位に限定できる。
- 製品単位での売却・分社(M&A)がしやすい。

## 代償
- 同一ユーザーの製品間シングルサインオンがない。
- 横断指標(MRR 等)は各製品からのイベント集約が必要(ADR-0002)。

## 将来の見直し条件
複数製品を同時契約する顧客が増え、共通ログインの要望が明確になった時点で、ID 連携(例: 共通 IdP)を別 ADR で検討する。既存プロジェクトの統合は行わない。

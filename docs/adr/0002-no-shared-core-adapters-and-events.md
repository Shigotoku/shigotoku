# ADR-0002: 共通基盤(Core)は作らず、アダプターとイベント契約だけ揃える

- 状態: 提案(承認待ち)
- 日付: 2026-11-27

## 背景
外部提案(`改善提案CHatGPT/`)は、全製品共通の Core(認証・契約・AI Gateway・Storage Gateway・Execution Gateway)を前提にしている。しかし現状は製品ごとに独立したスタックで、製品数が多く、共通基盤を先に作ると開発が分散するリスクが高い。

## 決定
1. **共通基盤は新設しない。** 製品ごとの独立を保つ。
2. **共通化は以下の「契約」だけ**を文書として定め、各製品が必要になったときに実装する。
   - **利用量・課金イベント**(JSON): `{ product, tenantId, plan, event, amount, unit, costJpy?, ts }`。各製品が自分の Firestore か Cloud Logging に書く。集約は後から BigQuery 等で行う。
   - **AI 呼び出しログ**: `{ product, tenantId, model, inputTokens, outputTokens, costJpy, ts }`。原文・個人情報は含めない。
   - **ストレージ参照**: 製品内に `StorageAdapter`(list/stat/read/write)のインターフェースを置き、Drive 以外は需要が出てから実装(DeckIt の `google-adapters` が先行例)。
3. コードの共有は**コピーではなくパターンの踏襲**を基本とし、同じコードが3製品以上で重複した時点で初めてパッケージ化を検討する。

## 理由
- 実需要(顧客・売上)が未確認の段階で抽象化すると、作り直しコストが大きい。
- イベント形式だけ揃えておけば、後から共通基盤・集計に移行できる。

## 代償
- しばらくは製品ごとの重複実装が残る。
- 横断のダッシュボードは、イベント実装が進むまで作れない。

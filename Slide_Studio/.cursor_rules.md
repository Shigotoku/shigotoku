# Cursor Project Instructions

You are rebuilding **DeckIt** (product name; repo folder `Slide_Studio`) from a Google Apps Script prototype into a production GCP SaaS.

Read first:
- docs/01_MASTER_REQUIREMENTS.md
- docs/02_CURSOR_IMPLEMENTATION_PLAN.md
- docs/03_DATA_MODEL.md
- docs/05_UI_UX_SPEC.md

Rules:
1. Do not continue HtmlService architecture.
2. Do not use google.script.run.
3. Do not port GAS global functions into React components.
4. Build domain interfaces first.
5. Drive/Slides behind adapters.
6. App shell renders before Drive data.
7. Guide/Settings/modals do not depend on backend.
8. Never white-screen on external API error.
9. Idempotency for create/generate.
10. legacy_gas/current is behavior reference only.
11. Preserve dark sidebar and four-step workflow.
12. Responsive desktop UI + E2E before all Google integration.
13. Do not branch on Google AI Pro/Workspace product names; use capabilities.
14. Keep user document bodies in Drive whenever feasible.
15. Inspect existing company GCP conventions before adding new infra.

First target: production-quality UI shell with mock data and Playwright tests; then Auth/Firestore/Drive.

Implementation root: `Slide_Studio/app` (Next.js), `packages/domain` (`@deckit/domain`), `e2e/`. Brand: **DeckIt**. See `docs/DECKIT-BRAND.md`, `docs/00_SHIGOTOKU_GCP_INTEGRATION.md`.

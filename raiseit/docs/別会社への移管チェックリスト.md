# レイジット (RaiseIt) 別会社・別ドメインへの移管チェックリスト

販売主体が決まった時点で、このリストに沿って移す。コード(`commercial/raiseit`)は、サイト固有の値を `.env` に集約し、メディトク固有の記述を持たない作りにしてある。

## 0. 先に決めること(コード外)

- [ ] 販売主体の法人名・ドメイン・ブランド名
- [ ] 開発コードの権利関係(メディトクのリポジトリで作ったコードを新会社が使う場合のライセンス/譲渡契約)
- [ ] 新会社の Google Workspace または Cloud Identity(独自ドメイン)
- [ ] プライバシーポリシー・利用規約・特定商取引法表記・問い合わせ窓口(OAuth審査とGBP API申請に必要)

## 1. Google Cloud(新会社の組織で作り直す)

- [ ] 組織・請求アカウント・プロジェクトを新規作成
- [ ] 有効化するAPI: Search Console API / Analytics Data API / PageSpeed Insights API / (承認後) Business Profile 系 / YouTube Analytics API
- [ ] サービスアカウント作成(鍵は作らない。組織ポリシーで禁止される場合が多い) → 実行環境のサービスアカウント(Cloud Run等)に権限を付ける
- [ ] OAuthクライアント作成 + 同意画面の設定 → ブランド/ドメイン確認 → 機密スコープの審査(顧客のGBP/GA4/Search Consoleを預かる場合)
- [ ] PSI用APIキーを新規発行(API制限: PageSpeed Insights API のみ)
- [ ] **GBP API 申請は新会社のプロジェクト番号で行う**(旧プロジェクトの許可は引き継がない)

## 2. コードの移行

- [ ] `commercial/raiseit` を新リポジトリへ(履歴を引き継ぐか、クリーンに移すかを決める)
- [ ] `.env` を新しい値で作成(`GSC_SITE_URL` / `GA4_PROPERTY_ID` / `PSI_API_KEY`)。`.env` は Git に入れない
- [ ] メディトク固有の文言・リンクがないか確認(`rg -i meditoku`)。現状: README・要件定義書の文脈説明のみ
- [ ] `医療広告チェッカー` のルールは医療向け。業種別ルールセットを分離する(医療 / 一般店舗)
- [ ] `issue-text.mjs` の DEFAULT_CONSTRAINTS(守ってほしい条件)を、顧客/業種ごとに差し替えられるようにする

## 3. 保存先・実行環境の載せ替え(GCP想定)

| 現在(ローカル)                | 移行先の目安                                                                  |
| ----------------------------- | ----------------------------------------------------------------------------- |
| `data/*.ndjson`(日次ファイル) | Cloud SQL(PostgreSQL)。まず同じ構造の表にそのまま入れる(`tenant_id` 列を追加) |
| Windows タスクスケジューラ    | Cloud Scheduler → Cloud Run Jobs                                              |
| `.env`                        | Secret Manager                                                                |
| `reports/*.html`              | 画面(Cloud Run)で動的に表示、またはCloud Storageに出力                        |
| 顧客のOAuthトークン           | Secret Manager + Cloud KMS で暗号化。分析データとは論理分離                   |

## 4. マルチテナント化(販売前に必須)

- [ ] すべてのデータに `tenant_id` を付与し、全クエリで強制する
- [ ] 顧客ごとの接続(GSC / GA4 / GBP / SNS)を登録・解除できる画面
- [ ] 認証(Firebase Authentication 等)と権限(管理者 / 担当者 / 閲覧のみ)
- [ ] 顧客データの全件エクスポートと、解約時の削除
- [ ] 監査ログ(誰がいつ何を承認・コピー・公開したか)

## 5. 現在の運用データの扱い

- [ ] とくなが内科胃腸科外科クリニックのデータ(Search Console / GA4)は、移管先で新しく接続し直す(旧データはCSV/NDJSONで持ち込み可能)
- [ ] メディトク自社サイトのデータは、新会社の顧客として扱うか、移管対象外にするかを決める

## 6. 移管後の確認

- [ ] `npm run check:auth` が通る
- [ ] `npm run fetch:all` / `fetch:src` / `fetch:events` / `fetch:psi` が通る
- [ ] `npm test`(医療広告チェッカーのテスト)が通る
- [ ] `npm run report` でレポートが生成され、「改善依頼」のコピーボタンが動く

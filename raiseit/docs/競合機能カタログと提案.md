### 2-3. 患者データとの距離(既存ルールとの整合)

- マーケティング分析基盤には**患者の診療内容・氏名・連絡先を入れない**(要件定義書 NFR)。
- 予約連携は `booking_id / location_id / campaign_id / 新患or再診 / 状態 / 日時 / 売上帯` 程度の**集計用最小項目**に限る。
- メディトクの既存サービス(受付・診察券など)と繋ぐ場合も、**件数などの集計値**のみ(個別患者は渡さない)。
- 要配慮個人情報を扱う必要が出たら、分析側とは別の保管領域に隔離し、仮名IDだけ分析側へ。

## 4. 競合が見落としがちな「勝てる追加機能」(全業種)

1. **再現性のある効果測定**: 施策の実施日を記録し、前後比較と信頼度を表示(「効果があった/不明」を正直に出す)。
2. **やらない提案も出す**: 効果が薄い施策・リスクが高い施策は「今月はやらない」と明示。
3. **変更の巻き戻し**: Git/変更履歴ベースで1クリックでロールバック(医療の誤公開対策)。
4. **データの持ち出し・解約時の返却**: 全データをCSV/JSONで出せる(中小/医療の安心材料)。
5. **固定費で使い放題の透明価格**: API従量を顧客に転嫁しない設計(X APIはBYO)。
6. **「できないこと」の明示**: データ鮮度・計測不能領域・推計値を隠さない。
7. **既存HP制作との相性**: Astro/WordPress/Wix等の差を吸収するPR/差分提示(Phase 2の対象)。
8. **オフライン計測の標準装備**: 電話番号・QR・来院時アンケート(「どこで知りましたか」)の集計。
9. **従業員の運用負荷ゼロ化**: 週1回5分の承認だけで回る「院長モード」。
10. **競合に勝つ根拠の提示**: 他社が「順位を上げた」としか言えない部分を、自社は「予約が何件増えたか」で語る。

## 5. 取り込まない/避けること

| 項目                                       | 理由                                              |
| ------------------------------------------ | ------------------------------------------------- |
| ★5レビューを増やす機能、特典付き口コミ依頼 | 景品表示法(ステマ規制)・Googleポリシー違反        |
| 治療効果に触れる口コミ返信の自動投稿       | 医療広告ガイドライン上のリスク                    |
| 完全自律で本文を書き換え公開               | 医療では誤公開のリスクが大きい。常に承認制        |
| Xの全アカウントを常時ポーリング            | APIコストが売価に見合わない。CSV/BYO/主要指標のみ |
| 患者個人データのマーケ基盤への投入         | 要配慮個人情報。集計値のみ                        |
| canonical / noindex / robots の自動変更    | 事故時の影響が大きい(要件定義書の方針)            |
| 「リアルタイム」の誇大表現                 | GBP等は日次が基本。データ別に鮮度を明示           |

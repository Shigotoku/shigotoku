# 仕事く SHIGOTOKU PLATFORM — マルチ環境対応追加仕様書 v4.0
2026-11-27 | v3.0マスター仕様書に対する優先差分・Cursor実装指示

## 1. 変更方針
v3の製品群、GCP Web本体、既存Deckit保護、承認・監査・法人分離を継承する。ただし「顧客Driveを正本とする」「他ストレージはP4のみ」「Googleログイン必須」という記述は本書で上書きする。正本は顧客が指定する保存先。保存先・AI・実行場所・認証を独立させる。Google非契約企業も利用できることを製品要件とする。既存Google連携を削除しない。初期の販売対象は一般中小企業・スタートアップ。医療顧客とのデータ混在禁止。

## 2. 共通構成
Web UI/API → Core（tenant、契約、認可、ジョブ、承認、監査）→ 製品 → Storage Gateway / AI Gateway / Execution Gateway。Content HubとKnowledge Hubは論理的な資産分類であり、物理保存先を固定しない。Google固有のファイルIDを製品の主キーにしない。既存DB・コードを調査し、アダプターを追加する方式を優先する。過剰なマイクロサービス化は禁止。

## 3. Storage Gateway
候補：Google Drive、OneDrive/SharePoint（Microsoft Graph）、Dropbox、Box、S3互換、GCS、Azure Blob、SFTP、ローカル、SMB/NFS共有、NAS。すべてのコネクタを初期実装しない。接続単位で読み取り元と書き込み先を指定し、異なる保存先への転送は明示承認を要求する。
共通契約：list(connection, folder, cursor), stat(ref), read(ref, range), write(destination, stream, expectedVersion, idempotencyKey), capabilities(connection), health(connection)。必要に応じて watch/changeCursor、exportNative、createFolder をオプション化。機能非対応は明示し、同等の機能があると仮定しない。ストリーミング、大容量、ページング、レート制限、再試行、失効、競合、部分失敗を扱う。
AssetRef = {tenantId, connectionId, provider, opaqueId, versionOrHash, mimeType, size, displayName, classification}。パス・URLは認可の代替にしない。接続ごとに許可ルート、用途、読み書き権限、データ分類を管理。メタデータ・検索索引も機密として扱い、索引化は許可範囲のみ。削除・権限失効を反映。原本は上書きせず、成果物は別名・別版で保存。既存DeckitのDrive IDは移行せずマッピング可能にする。

## 4. ローカル・NAS対応
A: ファイル選択/アップロードとダウンロードを全ブラウザ向け基準とする。対応ブラウザのみFile System Access APIでフォルダ選択・書き戻し。権限再取得、非対応ブラウザ、ページ終了後の自動処理不可を明示。
B: 仕事く Connect（仮称）をWindows優先、Mac次点で検証。Linux常駐は需要に応じて追加。既存のOSマウント済みSMB/NFSを利用し、NAS独自APIは必須にしない。外向きHTTPSのポーリング等でジョブ取得。インターネットへのSMB公開、受信ポート開放、任意コマンド実行は禁止。デバイス登録は短寿命ワンタイムコード、組織管理者承認、デバイス鍵・失効・ローテーション。署名付きジョブ、期限、nonce、tenant照合。許可された操作だけ実行する。
許可フォルダは管理者が指定し、正規化パス・シンボリックリンク・ジャンクション・UNC・TOCTOUを検査し、ルート外アクセスを拒否。OSの最小権限、資格情報はOS保護ストア。共有フォルダの権限は実行アカウントに従い、全社員の権限を代行しない。必要なら部署別接続。監視はdebounce、書き込み完了確認、定期再走査、ハッシュ重複排除、出力フォルダ除外。オフライン時は待機、再接続後に冪等再開。署名済み配布・更新・ロールバック、アンインストール、端末失効を設計。ローカルログに本文や鍵を残さない。
C: 社内常時稼働PC/サーバーにConnectを設置。サービスアカウント権限、監視、バックアップ、ネットワーク制約を検証。完全オンプレミスは別製品候補であり、GCPポータル依存のConnectと区別。

## 5. AI Gatewayとデータ経路
Workspace Studioは公式連携と契約条件が実証された場合のみ利用。Google AI Pro/Sparkの外部API利用枠転用は前提にしない。仕事く提供AIは当面メディトクの契約済み商用APIを候補とするが、第三者向けSaaS利用、法人間利用、データ保持・学習・地域・再委託条件を確認し、必要なら仕事く専用プロジェクト/契約へ分離する。APIキーはサーバー側Secret Manager等で管理し、ブラウザや配布Connectに埋め込まない。顧客別予算、利用量、モデル、原価、上限、同時実行を管理。BYOKは任意で別途暗号化・失効管理。ローカルLLMはOllama等の許可済みエンドポイントのみ、任意URLへのアクセス禁止。
データ処理ポリシー：cloud_allowed / local_processing_only / no_ai を基本とし、外部AIへの送信許可は別途明示。ローカル保存＋クラウドAIはローカル完結ではない。外部送信する項目、送信先、保存期間を表示し、必要な抜粋・マスキングを優先。クラウド禁止時は外部AI・クラウドレンダーへのフォールバックを禁止。GCPに送るメタデータも最小化。完全オフラインは別構成。顧客の同意なしにAIを切替えない。

## 6. Execution Gatewayと成果物
実行場所：Cloud Run/Jobs、Connectローカルワーカー、将来オンプレミス。ジョブに実行場所、入力/出力接続、データ分類、AI経路、テンプレート版、予算、承認状態を固定。クラウド処理時の一時ファイルは暗号化・期限削除、失敗時も清掃。ローカル処理は許可済みバイナリと固定引数、リソース上限、隔離、キャンセルを実装。任意スクリプト配布禁止。
Deckit：Google Slides経路を維持し、PPTX/PDFの独立レンダリングを検証。Google SlidesとPowerPointの完全互換を約束しない。Manualit：Meet以外のTeams文字起こし、TXT/VTT/SRT/DOCX、許諾済み音声を段階対応。DOCX/PDF出力。Reelit：MP4/サムネイル/投稿文を任意保存先へ。テンプレートのフォント・素材ライセンスとRemotion商用条件を確認。Google固有形式のエクスポートと一般形式を区別。

## 7. 認証・UX
Google OAuthを維持し、Microsoft Entra ID、メール認証を段階追加。ログインとストレージ接続は独立。メールドメインのみで所属を認可しない。管理者、編集者、承認者、閲覧者、デバイス管理者を区別。初回設定は保存先→AI→出力先→接続テスト。Google利用者には従来の簡単な導線を残す。設定画面に接続状態、最終同期、権限、処理場所、外部送信、原価上限を表示。一般利用者にAPI設定を強制しない。

## 8. 開発順序と受入条件
P0: 現行Deckit、v3仕様、既存認証・Drive・Studio・Meet実装を調査。回帰テストとADRを作る。P1: Driveアダプター化、ファイル入出力、PPTX/DOCX等の技術検証、AI Gateway商用API経路。P2: OneDrive/SharePoint PoC、Windows Connectで許可フォルダ読み書き。P3: Mac/共有フォルダ/監視・ローカル実行、Reelit/Manualit横断テスト。P4: 顧客需要に基づきその他クラウド、Linux、オンプレミス。既存Google顧客の移行を強制しない。
受入：同じ制作指示でDriveとローカルから入力し各保存先に出力、OneDriveでも実証。別tenant拒否、ルート外パス拒否、失効端末拒否、二重ジョブなし、オフライン復旧、上書き競合、容量不足、クラウド禁止時に外部送信ゼロ（通信監査で検証）、AIキー漏えいなし、既存Deckit回帰成功。費用・処理時間・品質・導入時間を計測。10/100/1000社の負荷とサポート費を試算。

## 9. Cursorへの実装指示
v3マスターと実装指示書を併読し、本書の差分を優先。最初に現状調査、依存箇所一覧、変更予定ファイル、最小アダプター契約、認証/データフロー図、脅威モデル、費用、PoC計画を報告。テストブランチでDriveとローカルの共通契約を実証する。既存本番変更、追加課金、破壊的移行、顧客データ転送、全コネクタ同時実装は承認なしに行わない。未確認API・契約条件は公式資料と実機で検証。製品名・価格・優先順位は仮案。

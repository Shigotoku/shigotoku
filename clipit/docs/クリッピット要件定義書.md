## 1. 戦略（なぜ勝てるか）

### 1.1 ポジショニング — 正面衝突しない

競合 Deep Research（`スクショマニュアル作成アプリ競合調査.md`）より、市場は「手動スクショ貼付」から「操作記録 + 生成AI + 多言語 + 閲覧ログ + タスク配信」へ進化済み。主要プレイヤーと弱点は以下。

| 競合 | 種別 | 価格（税抜目安） | クリッピットから見た弱点 |
|------|------|------------------|---------------------------|
| Teachme Biz | 国内エンタープライズ | エントリー 月額89,800円〜 | 小規模には重く高額 |
| Dojo / Dojoウェブ | 国内・買切/SaaS | 買切144万円 / 月37,500円 | 高額・導入が重い |
| COCOMITE | 国内エンタープライズ | 初期15万 + 月28,600円〜 | 初期費用と単価が高い |
| iTutor | 国内・買切 | 38万〜70万円 | 買い切り・小規模に不向き |
| NotePM | 国内・ナレッジ | 月4,800円〜 | 自動スクショ記録ではない |
| Scribe / Tango | 海外PLG | $12〜23/席（Team最低5席〜） | 日本語が不自然・席課金・紙文化に弱い |
| Guidde | 海外・動画AI | $18〜50/作成者 | 動画特化・日本語/紙運用に弱い |

> **勝ち筋:** 高機能エンタープライズ競争はしない。**「安い・簡単・すぐ使える・日本語と紙運用に最適・既読管理が低価格」** で、国内小規模現場（特に医療・士業・中小）に振り切る。

### 1.2 勝つポイント（競合の弱点 → クリッピットの強み）

| 項目 | 競合の弱点 | クリッピットの勝ち筋 |
|------|------------|------------------------|
| 導入 | 高額・営業問い合わせ・初期設定が重い | 無料登録・Googleログイン・5分で初回作成 |
| 価格 | 月数万円〜・席課金・年契約 | 無料あり・月980円〜・1施設/1社の定額 |
| UI | 高機能だが複雑 | 3クリックで作成開始・高齢スタッフでも迷わない |
| 日本語 | 海外ツールは不自然 | 日本語手順文に最適化 |
| 紙文化 | PDFはあるが現場貼付まで弱い | A4/B5印刷 + QRコード貼付に最適化 |
| 教育管理 | 大手は強いが高い | 既読確認・チェックリストを低価格で提供 |
| 業種特化 | 汎用が多い | 医療・士業・中小テンプレートを標準搭載 |
| エコシステム | 単独ツール | **ランウィズ / バジットのヘルプとして埋め込み**（シゴトク内連携） |

### 1.3 プロダクトの本質

> 本質は「マニュアルを作ること」ではなく **「人に教える手間を減らすこと」**。

機能優先順位：① 作成が簡単 → ② 見る人が迷わない → ③ 紙でもスマホでも見やすい → ④ 既読確認で教育管理 → ⑤ 更新が簡単 → ⑥ 安い → ⑦ セキュリティに配慮。

## 2.5 プロダクトの3本柱（Create / Manage / Teach）

| 柱 | 機能群 | 実装状況 |

## 3. 技術アーキテクチャ（ランウィズ / バジットと同一スタック）

### 3.1 スタック

| レイヤ | 技術 | 用途 |
|--------|------|------|
| LP | **Astro 6** + Tailwind CSS 4 | `shigotoku.com/clipit/`（ランウィズ/バジット LP と同一構成） |
| Web アプリ | **React 19 + Vite 8** + Tailwind CSS 4 + React Router 7 | `app.clipit.shigotoku.com`（編集・管理・閲覧者向け SPA） |
| API | **Cloud Functions v2（Express 5）** | `/api/**`（AI生成・PDF生成・マスキング確定・共有トークン・既読・QR） |
| **Chrome 拡張** | **Manifest V3 + TypeScript + Vite** | 操作記録・スクショ取得（**新パイプライン。下記 §6**） |
| 認証 | Firebase Authentication | Google / メール（閲覧者は認証不要） |
| DB | Cloud Firestore | 組織・ユーザー・マニュアル・ステップ・既読・フィードバック |
| ストレージ | Cloud Storage | スクショ原本・マスク確定画像・ロゴ・生成PDF |
| AI | **Gemini API**（Google AI） | 日本語手順文生成・注意文/FAQ提案・マニュアル健康診断 |
| スケジュール | Cloud Scheduler + Functions | 賞味期限通知・未読リマインド・UI差分検知（Phase 3） |
| 秘密情報 | Secret Manager | `GEMINI_API_KEY` 等 |
| 配信 | Firebase Hosting | LP（静的）+ SPA + API リライト |

> **方針:** バジットに倣い **API を持つ**。ランウィズ（クライアント直Firestore）では、PDFサーバー生成（Puppeteer）・画像マスク確定・AI生成のレート制御・推測困難な共有トークン発行が安全に実装できないため。

### 3.2 採用しないもの

- **Supabase / AWS / Vercel / Netlify** — 使用しない（GCP統一）
- **AI自動マスキング（初期）** — 医療情報の見逃しリスクのため Phase 2以降に「候補提示型」で導入
- **ネイティブアプリ初期投入** — 閲覧は PWA / Web で完結
- **デスクトップアプリ記録（初期）** — まず Chrome 拡張に集中（Phase 4 で検討）

### 3.3 Firebase プロジェクト分割（ランウィズと同じ思想）

認証テナント分離・セキュリティのため、**専用プロジェクトを新設**する（ランウィズが `shigotoku-runwith-prod` を持つのと同じ）。

| Firebase プロジェクト ID | エイリアス | ホストするもの |
|--------------------------|-----------|----------------|
| `shigotoku-clipit-prod` | `clipit` | クリッピット アプリ + API + Firestore + Storage |
| `shigotoku-prod`（既存） | `buzzit` | コーポレート + **クリッピット LP（サブパス）** |

> LP はランウィズ/バジット同様、コーポレートと同じ `shigotoku-prod` の Hosting にサブパスで同居。アプリ/APIのみ専用プロジェクト。

## 4. URL 設計（既存と完全一致 — `/` の付け方も同じ）

### 4.1 本番 URL マップ

| URL | 内容 | Hosting |
|-----|------|---------|
| `https://shigotoku.com/clipit/` | クリッピット LP | `shigotoku-web`（サブパス） |
| `https://shigotoku.com/clipit/pricing/` | 料金ページ | 同上 |
| `https://app.clipit.shigotoku.com/` | アプリ（編集・管理） | `shigotoku-clipit-app-ad9ee` |
| `https://app.clipit.shigotoku.com/api/**` | API（Hosting リライト → Functions） | Cloud Functions |
| `https://app.clipit.shigotoku.com/m/{token}` | 共有マニュアル閲覧（QR/URL先・**認証不要**） | SPA（noindex） |

### 4.2 `/`（トレイリングスラッシュ）と SEO ルール — 既存準拠

既存 `deploy/build.mjs` / `deploy/build.config.mjs` の慣習をそのまま踏襲する。

| ルール | 内容（ランウィズ/バジットと同一） |
|--------|-----------------------------------|
| LP の Astro `base` | `'/clipit/'`（末尾スラッシュ必須） |
| LP の Astro `site` | `'https://shigotoku.com'` |
| sitemap の URL | **すべて末尾 `/` 付き**（例: `/clipit/`, `/clipit/pricing/`） |
| robots.txt | `Allow: /clipit/` を追記 |
| LP（公開） | OGP / Twitter Card / 構造化データ（SoftwareApplication）/ canonical を付与・**インデックス対象** |
| アプリドメイン | `X-Robots-Tag: noindex, nofollow`（ランウィズ/バジット アプリと同じ） |
| 共有マニュアル `/m/{token}` | **noindex**（顧客情報・院内情報を含むため検索インデックス対象外。これが安全な既定値） |
| 環境変数 | LP は `PUBLIC_*`、アプリは `VITE_*`（ビルド時インライン） |

> **共有ページのSEO補足:** マニュアル共有URLは原則 noindex。SaaS事業者向けの「公開ヘルプセンター」ユースケース（Phase 3）でのみ、組織がオプトインした場合に `shigotoku.com/clipit/help/{org}/...` のインデックス可能な静的出力を別途用意する。医療・中小の既定は常に noindex。

## 5. フォルダ構成（モノレポへの組み込み）

ランウィズ/バジットと同型で `clipit/` を新設する。

```
shigotoku/
├── clipit/
│   ├── landing-page/        ← LP（Astro）  base: '/clipit/'
│   ├── app/                 ← アプリ（React + Vite）
│   ├── api/                 ← API（Cloud Functions v2 / Express）
│   ├── extension/           ← ★ Chrome 拡張（Manifest V3 / Vite）※新パイプライン
│   └── docs/                ← 本書ほか（要件・課金・競合）
├── corporate-site/          ← 既存（/clipit/ への導線を追加）
├── deploy/                  ← build.mjs / build.config.mjs に clipit を追記
└── ...
```

### 5.1 LP / アプリ / API（既存と同じ作り方）

- **LP** … `clipit/landing-page/astro.config.mjs` に `base: '/clipit/'`, `site: 'https://shigotoku.com'`、`src/lib/urls.ts` で `appPath` / `sitePath` / `assetPath`（ランウィズ LP と同一）
- **アプリ** … `src/{pages,components,layouts,lib,store,services,types}` 構成。SPAフォールバック（`** → /index.html`）
- **API** … `src/index.ts` → Cloud Functions エクスポート（バジット `buzzitApi` と同型で `clipitApi`）

### 5.2 Chrome 拡張（既存2プロダクトに無い新要素）

| 項目 | 内容 |
|------|------|
| 場所 | `clipit/extension/` |
| 規格 | **Manifest V3** |
| 構成 | `manifest.json` / `background`（service worker）/ `content script`（クリック・DOM・スクショ要求）/ `popup`（記録開始/停止UI）/ `offscreen`（必要時の画像処理） |
| ビルド | Vite（独立。`npm run build` → `dist/`） |
| 配布 | **Chrome ウェブストア**（Firebase Hosting ではない）。`.zip` を Developer Dashboard へアップロード |
| 認証連携 | アプリ（`app.clipit...`）の Firebase ID トークンを拡張へ受け渡し（`chrome.identity` or アプリ→拡張メッセージング）。API 呼び出しは `Authorization: Bearer` |
| キャプチャ | `chrome.tabs.captureVisibleTab` でスクショ、`content script` でクリック座標・要素テキスト・role・URL・ページタイトル取得 |
| **強制キャプチャ** | `Alt + Shift + S` でクリックに依存せず即時スクショ + ステップ追加（**Gemini 提案②**。SPAでクリックを取り逃す問題への必須対策） |

> **重要な設計判断（CI/CDへの影響）:** 拡張は Firebase デプロイ対象外。`deploy/build.mjs` は拡張をビルドするが**配布はしない**（成果物 `.zip` を生成するのみ）。GitHub Actions の本番デプロイは LP/アプリ/API のみ。拡張の公開は手動レビュー後にウェブストアへ。

## 7. アプリ 機能要件（MVP の定義）

MVPは「競合全部入り」ではなく **日本の小規模現場がすぐ使える最小構成**。

### 7.1 MVP 必須

|------|------|
| Googleログイン | Firebase Auth |
| 組織作成 | 初回ログイン時に自動作成（施設名・会社名・ロゴ） |

| 拡張からの記録取り込み | 拡張 → API → Firestore/Storage |

| ステップ編集 | 並び替え・削除・追加・文言修正・スクショ差し替え |

{ loc: 'https://shigotoku.com/clipit/',         changefreq: 'weekly',  priority: '0.9' },
{ loc: 'https://shigotoku.com/clipit/pricing/', changefreq: 'monthly', priority: '0.8' },

```js
export const MANUALTOKU_APP_URL = 'https://app.clipit.shigotoku.com';

export const MANUALTOKU_FIREBASE = { /* shigotoku-clipit-prod の Web 設定 */ };

// projectEnv に追加
'clipit-landing': { PUBLIC_APP_URL: MANUALTOKU_APP_URL, PUBLIC_GA_MEASUREMENT_ID: GA_MEASUREMENT_ID },
'clipit-app':     { VITE_LANDING_URL: MANUALTOKU_LP_URL, VITE_FIREBASE_*: ... },
```

### 14.3 `.firebaserc` / Hosting ターゲット

```
projects: { "clipit": "shigotoku-clipit-prod" }
targets:  shigotoku-clipit-prod-ad9ee → hosting: { "clipit-app": ["shigotoku-clipit-app-ad9ee"] }
```

`deploy/firebase.clipit.json` を新設（`runwith-app` 構成 + Functions/Storage/Firestore を参考）。アプリ Hosting には既存と同じ `X-Robots-Tag: noindex, nofollow` ヘッダを付与。

### 14.4 `deploy/package.json` スクリプト追加

```
deploy:clipit-app, deploy:clipit-api, deploy:clipit（一式）
deploy:all / deploy:all-with-api に clipit を連結
```

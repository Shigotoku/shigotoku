# クリッピット：1000ユーザー規模のユニットエコノミクスと安全・コスト設計

**版:** 1.0（2026-06-03）  
**前提インフラ:** GCP（Firebase Hosting / Firestore / Storage / Cloud Functions v2）  
**AI:** Google に限定しない（推奨は下記 §4）

---

## 1. 「1000ユーザー」の定義

| 指標 | 典型の意味 | 本ドキュメントの基準シナリオ |
|------|------------|------------------------------|
| 登録アカウント数 | ログイン可能な人数 | **1,000 MAU** |
| 組織数 | 課金・データの単位（クリニック/会社） | **約 400 組織**（1 組織あたり平均 2.5 名） |
| 有料組織 | MRR の源泉 | **60 組織（15%）** — B2B SaaS の初期として妥当 |

> 利益率は **組織あたり ARPU** と **AI・ストレージの使い方** で大きく変わる。必ずシナリオ比較する。

## 3. コストモデル（GCP + AI）

### 3.1 利用行動の仮定（1,000 MAU / 400 組織）

| 行動 | 月間量 |
|------|--------|
| 新規マニュアル | 800 本（有料組織中心、無料は上限近くまで使う組織は少数） |
| 1 本あたり手順 | 8 ステップ |
| スクショ | 1 枚 150KB WebP 平均、手順あたり 1 枚 |
| AI 文案生成 | 有料: 組織あたり 120 回/月、無料: 組織あたり 8 回/月 → **約 9,920 回/月** |
| 公開閲覧（共有 URL） | 30,000 PV、1 PV あたり 500KB 画像 CDN 相当 |

### 3.2 インフラ（Blaze・東京リージョン概算）

| サービス | ドライバ | 月額（円・$1=150円） |
|----------|--------|-------------------:|
| Firestore 読取 | ダッシュボード・一覧・既読 | 3,000〜8,000 |
| Firestore 書込 | マニュアル・既読 | 1,500〜3,000 |
| Cloud Storage | 累積 80GB + 新規 12GB/月 | 2,000〜4,000 |
| Functions `clipitApi` | 120k 呼び出し、256MB、200ms 平均 | 2,000〜6,000 |
| Hosting / 転送 | SPA + 画像 egress | 1,500〜5,000 |
| Secret Manager / ログ | 少数シークレット | 500〜1,000 |
| **インフラ小計** | | **約 1.1万〜2.7万円** |

Firebase の無料枠内に収まる段階（MAU 数百）では **月数千円** 程度。上記は **1000 MAU で実利用が乗った後** のレンジ。

### 3.3 AI API（最大の変動費）

1 回の「手順文案」生成（テキストのみ、約 2k トークン往復）:

| プロバイダ例 | 単価イメージ | 9,920 回/月 |
|--------------|--------------|------------:|
| Gemini 2.0 Flash | 極小（$0.1/1M 級） | **数百〜2,000 円** |
| OpenAI GPT-4o-mini | 中 | **5,000〜15,000 円** |
| マルチモーダル ingest（画像→手順） | 1 回 5 画像 × 高トークン | **+1〜5 万円**（使った分だけ） |

**方針（コスト抑制）:**

1. 文案生成は **Flash 系の最安モデル** をデフォルトに。
2. 画像理解（ingest）は **オプション**・ステップ数上限・月間クォータで cap（`assertAiQuota` と同様）。
3. `GEMINI_API_KEY` 未設定時の **ルールベース fallback** は本番でも「超過時のセーフティネット」として維持。
4. プロバイダは **アダプタ層**（`clipit/api/src/services/ai/`）で差し替え可能にし、Google 固定にしない。

### 3.4 人件費・固定費（見落としやすい）

| 項目 | 月額目安 | 備考 |
|------|--------:|------|
| サポート（セルフサーブ前提） | 0〜3 万 | 問い合わせ 2%/月 × 30 分 |
| パートタイム CS 1 名 | 8〜15 万 | 1000 MAU 超で検討 |
| 法務・監査（医療向け） | 按分 | 利用規約・個人情報の見直し |

## 4. 利益率シナリオ（月次）

| シナリオ | ネット売上 | インフラ+AI | サポート | **営業利益** | **利益率** |
|----------|----------:|------------:|---------:|-------------:|-----------:|
| A 低利用・Flash AI | 163,900 | 15,000 | 0 | **148,900** | **91%** |
| B 標準（本表の利用） | 163,900 | 35,000 | 30,000 | **98,900** | **60%** |
| C ヘビー AI + ingest | 163,900 | 80,000 | 30,000 | **53,900** | **33%** |
| D 有料転換 8% のみ | 87,000 | 25,000 | 20,000 | **42,000** | **48%** |

**解釈:**

- **1000 MAU・有料 15%・標準利用** なら **粗利率 60% 前後** は現実的。
- **利益を壊す要因** は (1) マルチモーダル AI の無制限利用 (2) 無料組織への Storage 肥大 (3) サポート人件費。
- MRR が **17 万円** の段階では **フルタイム CS を雇うと利益率は一気に落ちる** → ドキュメント・チャットボット・上限表示で自助化。

### 4.1 損益分岐（ざっくり）

- 固定費 0・変動費のみなら **有料 3〜5 組織（スタンダード）** でインフラは回収可能。
- **人件費 30 万/月** を載せるなら MRR **50 万円以上**（有料 150〜200 組織相当）を目安。

## 5. 安全性（優先度付きロードマップ）

### 5.1 実装済み（2026-06-03）

| 対策 | 内容 |
|------|------|
| プラン上限（作成） | 月間マニュアル数を Firestore 集計で強制 |
| AI クォータ | 組織×月の `clipit_usage` + API レート制限 |
| Firestore ルール | 組織メンバーのみ `clipit_manuals` 書込、共有トークンは read のみ公開 |
| 共有 | 推測困難トークン + 公開用スナップショット（本番データと分離） |

### 5.2 短期（コストほぼゼロ）

| 対策 | 効果 |
|------|------|
| **Firebase App Check** | 不正クライアント・スクレイピング抑制 |
| 共有トークン **有効期限・失効** | 漏洩時の被害時間を限定 |
| 画像アップロード **サイズ・MIME 制限** | Storage コスト・マルウェアリスク低減 |
| **CORS / Origin 固定**（API） | 第三者サイトからの API 悪用防止 |
| 監査ログ（`clipit_audit`） | 管理者操作・プラン変更の追跡 |

### 5.3 中期（医療・士業向け）

| 対策 | 効果 |
|------|------|
| 手動マスキング必須フロー（公開前確認） | PHI 漏洩リスク低減（要件どおり） |
| EXIF 除去・画像再エンコード | 位置情報・端末情報の除去 |
| Cloud Armor / API Gateway レート制限 | Functions 前段での DDoS・コスト爆発防止 |
| バックアップ・PITR（Firestore） | 誤削除・障害復旧 |
| Stripe + サーバー側 `plan` のみ更新 | クライアント改ざん防止 |

### 5.4 AI プロバイダ選定（Google 非限定）

| 用途 | 推奨 | 理由 |
|------|------|------|
| 日本語手順文 | Gemini Flash / GPT-4o-mini / Claude Haiku | 品質と単価のバランス。A/B で品質評価 |
| 画像→手順（ingest） | Gemini Flash（マルチモーダル）または GPT-4o-mini vision | 回数を厳しく cap |
| 機密性が高い案件 | **GCP Vertex AI（同一リージョン）** | データ所在地・契約の整理がしやすい |

## 6. ユーザー満足度とコストの両立

1. **無料でも「1 本完成」まで迷わない** — オンボーディング・テンプレ（成功体験）。
2. **上限に達したら** — 理由とプランを日本語 1 文で表示（実装: `assertCanCreateManual` / API 429）。
3. **AI は「一括生成」より「1 手順ずつ」デフォルト** — 失敗時の無駄コストとユーザーストレスを減らす。
4. **画像は WebP・最大辺 1280px** — 閲覧品質を保ちつつ Storage/転送を半減。（**実装済み** → `OPERATIONAL-COST.md`）
5. **共有ページは静的スナップショット** — 公開閲覧が Firestore 本番を読み放題しない。

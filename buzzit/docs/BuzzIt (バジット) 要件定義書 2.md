BuzzIt (バジット) 要件定義書 【完全版】

1. プロジェクト概要

1.1. プロダクト名

BuzzIt（バジット）

1.2. コンセプト・ビジョン

「SNSツール」ではなく、「組織を動かし、売上を作る経営OS」
「SNS運用を毎朝5分のルーティンで終わらせる」「担当者の孤独をなくし、全社員を巻き込む」を実現する、BtoC店舗ビジネス向けのSNS統合管理・自動化SaaS。

1.3. ターゲットユーザー

初期ターゲット (ボウリングピン戦略): 美容室・サロン（1〜数名規模から多店舗展開まで）

拡張ターゲット: 飲食店、パーソナルジム、小規模EC、教育系などのBtoC事業者

ペルソナ: 日々の業務に追われSNSに割く時間がない経営者・店長、ネタ出しに疲弊し孤立しているSNS担当者。

2. ビジネス要件・戦略

2.1. 解決する課題 (ペイン)

運用負荷と属人化: 何を投稿すべきか分からず、複数SNSへの展開に手間がかかりすぎる。

分析の形骸化: 既存ツールはグラフが出るだけで、具体的な「次の行動」を提示しない。

組織の分断: SNSが担当者一人の孤独な作業になっており、現場のリアルな知見が活きない。

成果の不透明さ: フォロワーは増えても、売上（予約・来店）に繋がっている実感がない。

2.2. 提供価値 (バリュー)

思考ゼロのUX: ユーザーはAIが提示した「今日やること（台本を読む・承認する）」だけを実行。

一気通貫の自動化: 1本の動画/テキストから全SNSへ最適化展開し、改善までを自動化（Auto Mode）。

全社巻き込み: Slack連携等を通じ、摩擦ゼロで社員のアイデアを吸い上げ、成果を還元する。

2.3. KPI設計 (重要指標)

投資家およびユーザーが経営判断に用いる本質的なKPIを以下に定義し、ダッシュボードで可視化する。

認知: リーチ数（見られているか）

興味: 保存率・シェア率（欲しいと思われているか）

誘導: URLクリック率（売上に近づいているか）

見込み客: LINE公式アカウント友だち追加数

成果: 最終的な売上・予約数（投稿ごとの貢献度）

2.4. PLG戦略 ＆ Growth Loop（爆発的拡散構造）

広告費に依存せず、プロダクト自体が新規顧客を連れてくるループを構築する。

ループ構造: ユーザーが利用 → 成果発生（フォロワー増・売上） → アプリ内から「成果をSNSで共有」 → 新規ユーザーが流入 → 無料診断を経て登録。

透かし（ウォーターマーク）: 無料プランの生成物には「Powered by BuzzIt」を明記し、バイラル効果を狙う。

テンプレ市場: バズった投稿型をユーザー間で共有・売買し、ネットワーク効果を最大化する。

2.5. マネタイズ・プラン設計

Starter (0円): PLGエンジン。AI台本生成、SNS健康診断。※投稿に透かしあり。

Pro (4,980円/月): 利益基盤。全SNS自動予約、AI処方的提案、透かし削除。

Team (9,800円/月) [本命]: LTV最大化。Slack連携（ネタ会議）、戦略的通知システム。

Growth OS (29,800円/月): 経営インフラ。深い売上トラッキング、Auto Mode（完全自動運用）、アンバサダーCRM。

※将来的に成果報酬（LINE登録1件につき〇円等）の導入も検討。

3. システムアーキテクチャ・技術要件

3.1. 基本方針

スクレイピング絶対禁止: 規約違反・アカウント凍結リスクを排除するため、データ取得・投稿は公式APIの範囲内で行う。

アグリゲーションAPI: 各SNSの仕様変更を吸収するため、「Ayrshare」等の統合APIをミドルウェアとして採用。

3.2. コスト最適化エンジン

プロンプトキャッシュ: 類似業種へのAI提案結果をDBにキャッシュし、APIトークン消費を大幅に削減。

段階的SLM移行: データ蓄積後、安価なオープンソース小規模言語モデル（Llama 3等）のファインチューニング版へ移行。

ルールベース・キューイング: 全データをAIに投げず、ルールベースで一次処理。また、APIのレートリミットを回避する非同期ジョブキューを実装。

4. コア機能要件 (SaaS本体)

4.1. SNS経営コクピット & 深い売上トラッキング

極限のシンプルUI: 複雑なグラフを排除し、現在の「健康スコア」と「今日のミッション（処方的提案）」を最上段に配置。

売上可視化: 「投稿 → LINE/LP遷移 → 来店 → 売上」のファネルをトラッキング。「このショート動画が32万円の売上を創出した」とダッシュボードで明示する。

4.2. マジック・クリエイター (制作・展開エンジン)

Repurpose（1→多変換）: 1本のショート動画/台本から、Xスレッド、IGカルーセル用テキスト、LINE配信文を自動生成。

自動ABテスト: AIがタイトル・フック・サムネイルの別パターンを複数生成・テスト投稿し、勝ちパターンを自動抽出。

自動キャンペーン生成: フォロワー獲得用の「リポストでプレゼント」等の企画、バナー案、規約文面をAIが自動生成。

4.3. Auto Mode (AI完全自動運用) ※上位プラン

ユーザーの指示を待たず、AIが内部データに基づき**「投稿自動生成 → 自動スケジュール予約 → 結果分析 → 次の改善」**のサイクルを自律的に回す。

ユーザー（経営者）は、AIから上がってきた提案に対して「承認（Approve）」ボタンを押すだけで運用が完結する。

4.4. トレンド波乗りエンジン (Trend-Hijacking)

プラットフォーム内で急上昇している「人気音源」や「バズフォーマット」を検出。

自社の過去の良質なテキスト/画像アセットを、そのトレンドに合わせたショート動画台本としてAIが再構築して提案する。

4.5. 勝ちテンプレ市場 (投稿マーケット)

ユーザーのアカウントで成果を出した「バズの型（匿名化データ）」をプラットフォーム上で共有・売買可能にするネットワーク機能。

5. 組織化・外部連携機能

5.1. 組織を動かす「戦略的通知システム」 (Slack / LINE)

単なるアラートではなく、組織の行動を促すための時間軸を持った通知設計。

【朝】全社レポート: 前日の成果（リーチ・売上）と、AIからの「今日の一言アドバイス」を全社員に共有。

【昼】投稿確認・承認: 担当者/社長へ「本日の投稿が生成されました。承認しますか？」というアクション要求。

【夜】バズ通知: 「〇〇さんのアイデアがバズり始めました！全員でいいねしましょう」とリアルタイムの熱狂を共有。

5.2. 社員巻き込み「Slackネタ出し会議」

社員が専用Slackチャンネルに現場の気づきや写真を投稿。

AIが即座に「バズフォーマット化された台本」に整形してスレッド返信。

社内のスタンプ（🔥等）でウケを可視化し、管理者が「ワンタップ採用」ボタンを押すとアプリの撮影キューへ自動追加。

5.3. マイクロアンバサダーCRM (UGC創出)

自社関連ハッシュタグ投稿者を自動リスト化＆スコアリング。

API制限（1時間〇〇件等）を遵守したキューイングにより、優良顧客へ「限定クーポン」や「アンバサダー招待」DMを自動送信。

5.4. 代理店向けホワイトラベル (BtoBtoC展開)

個人のSNS運用代行フリーランスや代理店向けに、複数クライアントアカウントを一括管理・切り替えできる「マルチテナントダッシュボード」を提供。彼らをBuzzItの販売チャネル化する。

6. 非機能要件

UI/UX: 「思考コストゼロ」。ユーザーに「次どうするか」を考えさせない導線設計。

ブランドセーフティ: AI生成物が医療・薬機法NGワードや不適切表現を含まないか判定する事前フィルター。

7. MVP開発とスケールアウト・ロードマップ

Phase 1: MVP（コア検証・手動運用）

目的: 自社(RunWith)での実績作り。

実装: AI台本生成、Repurposeエンジン（1→多変換）、手動トリガーでのAyrshare一括予約、簡易ダッシュボード。

Phase 2: 組織化 ＆ PLG始動

目的: アーリーアダプター（美容室等）獲得、口コミループ構築。

実装: Slack連携（ネタ会議）、戦略的通知（朝/昼/夜）、透かし付与、LP連動「無料アカウント診断」、ABテスト機能。

Phase 3: 経営OS化 ＆ スケーリング

目的: LTVの最大化、高単価プランの販売。

実装: 深い売上トラッキング（CV計測）、Auto Mode（完全自動化）、トレンド波乗りエンジン、自動キャンペーン生成、アンバサダーCRM。

Phase 4: エコシステム完成

目的: 市場シェアの独占、ネットワーク効果の最大化。

実装: 勝ちテンプレ市場、代理店向けホワイトラベル提供、プロンプトキャッシュ・SLM移行による原価率の極小化。

# メディトク X 投稿 — Buffer 経由セットアップ（BuzzIt）

X API の無料枠終了後、**メディトク公式 X への予約投稿**は BuzzIt → **Buffer → X** が推奨ルートです（実装: `buzzit/api/src/services/buffer.ts`）。

## 登録メール（方針: Google Workspace の @meditoku.com）

**推奨:** `sns@meditoku.com` のような**役割用**が理想。すぐ用意できない場合は、担当者の **`あなたの名前@meditoku.com`** で登録し、パスワードを社内の共有保管に入れる。

- Buffer のログインは **会社ドメイン**にしておくと、引き継ぎ・監査がしやすい。
- 「ほとんど使わない個人 Gmail」は、再設定メールや通知の見逃しで止まりやすいので使わない。

## 投稿先（メディトク公式 X）

- Buffer ダッシュボードで **メディトクの X を「チャンネル」として接続**（接続時に X 側でメディトクアカウントにログイン）。
- 投稿されるのは **接続した X チャンネル**で決まる（Buffer ログインが誰のメールかは投稿アカウント名には影響しない）。

注意（社内運用）:

| 項目 | 推奨 |
|------|------|
| ログイン情報 | 共有パスワード管理（退職時の引き継ぎ） |
| API キー | BuzzIt の「メディトク用キャラ」にだけ紐付け。他社・他ユーザー向けに同じキーを流用しない |
| 利用許諾 | Buffer API は自社の内部連携向け。BuzzIt を SaaS 販売する際に「Buffer 代わり」に使うのではなく、**自社アカウントの投稿自動化**として使う |

## 手順（初回 15 分程度）

1. [Buffer](https://buffer.com) 無料プランに登録（**@meditoku.com** でサインアップ）
2. Buffer で **X（メディトク公式）をチャンネル追加**（無料は最大 3 チャンネル）
3. [Buffer Developers](https://developers.buffer.com/) または Buffer の設定から **API キー（個人用 / Personal access token）** を発行
4. BuzzIt → **設定 → SNS → X** →「Buffer 経由で X に投稿」
   - API キーを入力 → **チャンネルを取得** → メディトクの X を選択 → **このキャラの X 投稿先にする**
5. **投稿候補 / カレンダー**で X 向けに予約。時刻になると BuzzIt が Buffer に渡し、約 2 分後に X へ公開

## 上限の目安（2026 年時点・要公式確認）

- 無料: 3 チャンネルまで
- API: おおむね **30 日で 3,000 リクエスト（アカウント全体で共有）**、1 投稿 ≒ 1 リクエスト
- メディトクが 1 チャンネルだけなら、通常の予約投稿用途では十分なことが多い
- **スレッド（複数ポスト）は未対応** → 280 字以内の 1 本にするか、X API 直接投稿を使う

## 動作確認

1. テスト用の短文を 3 分後に予約
2. カレンダーで「投稿済み」になるか確認
3. [Buffer のキュー](https://publish.buffer.com/) と X のタイムラインで実投稿を確認

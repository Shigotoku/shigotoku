## 1. プロダクトビジョン

### 1-1. 本質

本プロダクトは単なる「スピーチ練習アプリ」ではない。

> **意思決定突破ツール（Decision Breakthrough Engine）**

ユーザーが目指すのは「上手に話すこと」ではなく **「通すこと」** である。

### 1-2. 戦略的差別化

既存のスピーチコーチ・発音アプリ・翻訳アプリとは一線を画し、  
**「意思決定突破 × 英語適応 × 即応耐性 × 成長可視化」** を統合した、市場に存在しないポジションを確立する。

### 1-3. ユーザージャーニー（進化モデル）

ユーザーはA層から入り、自然にB層へ引き上げられる設計とする。

```
Stage 1 ─── 話せるようになる（A層・入口）
  │  フィラー除去、ペース可視化、構造診断
  │
Stage 2 ─── 通せるようになる（A層・深化）
  │  勝率スコア、圧迫モード、想定質問生成
  │
Stage 3 ─── 英語で戦えるようになる（B層）
     日本語→英語変換、Speakable English、発音トレーニング、文化適応解析
```

## 3. システムアーキテクチャ

### 3-1. 提供形態（多層構造・ファネル戦略）

```
┌──────────────────────────────────────────────┐
│  1️⃣  Chrome拡張（無料導線・集客）              │
│      Google Slides連動サイドバー               │
│      → 体験させて有料アプリへ誘導              │
├──────────────────────────────────────────────┤
│  2️⃣  ローカルアプリ（Electron / Tauri）        │
│      Mac / Windows 両対応                     │
│      全ファイル形式対応                        │
│      コア機能すべてを提供                      │
└──────────────────────────────────────────────┘
```

**Chrome拡張の役割を明確に限定する（技術的制約への対応）:**

- Manifest V3 環境ではバックグラウンド音声処理に厳しい制約がある
- Chrome拡張は **「スライド取り込み＋簡易プレビュー＋1スライドAI修正」** に徹する
- 録音・AI処理・全体最適化はすべてローカルアプリに集約する
- Chrome拡張はローカルアプリへの **「ブリッジ（橋渡し）」** として設計する

### 3-2. AI・音声処理（コスト最小化・プライバシー設計）

| レイヤー | 方式 | コスト |
|----------|------|--------|
| 文字起こし | Web Speech API / OS標準認識 / ローカルWhisper | **無料** |
| AI処理（基本） | BYOK（ユーザーのOpenAI/Gemini APIキー持ち込み） | **運営コスト0** |
| AI処理（上位） | Managed AI（運営がAPIを提供） | Smart/Enterpriseプラン |
| AI処理（完全ローカル） | Ollama等のローカルLLM | **無料** |

**プライバシー原則:**

- カメラ使用は明示的な同意制・ON/OFF設定
- ログ保存はON/OFF選択可能
- 録音データはローカルに保存（クラウド送信はユーザー選択制）
- BYOK時はAPIキーをローカルにのみ保存

### 3-3. 技術スタック

| 層 | 技術 |
|----|------|
| フロントエンド（Chrome拡張） | HTML/JS + Chrome Extension API (Manifest V3) |
| フロントエンド（ローカルアプリ） | Electron または Tauri |
| バックエンド | Python (FastAPI) / Node.js |
| 音声認識 | openai-whisper（ローカル）/ Web Speech API / OpenAI API |
| AI処理 | OpenAI API / Gemini API / Ollama（ローカルLLM） |
| PDF処理 | PyMuPDF |
| 認証・決済 | Stripe + クラウドライセンス認証 |
| オフライン対応 | ローカルWhisper + ローカルLLM で完全オフライン稼働可能 |

### 3-4. データ設計

```
Session（セッション）
├── id: UUID
├── title: セッション名
├── created_at / updated_at
├── slides: スライドファイル参照
├── target_type: "vc" | "ringi" | "academic" | "interview" | ...
├── target_duration: 目標発表時間（秒）
│
├── iterations[]: 練習イテレーション配列
│   ├── iteration_number: 練習回数
│   ├── recording: 録音ファイル参照
│   ├── transcript: 文字起こしテキスト
│   ├── slide_timings[]: スライドごとの発表時間
│   ├── improved_script: AI改善原稿
│   ├── analysis: 解析結果
│   │   ├── filler_count: フィラー数
│   │   ├── wpm: 話速
│   │   ├── hedging_words[]: 弱気ワード一覧
│   │   ├── energy_map: 熱量マップデータ
│   │   ├── structure_score: 構造診断スコア
│   │   └── pitch_score: 勝率スコア
│   └── timestamp
│
└── growth_log: 成長記録
    ├── score_history[]: スコア推移
    └── improvement_rate: 改善率
```

### 🧠 Aレイヤー：プレゼン突破エンジン（日本語ベース）

#### 4-1. 原稿彫刻エンジン（Refinement Engine）

反復練習の核となる「録音→文字起こし→AI改善→再練習」ループを提供する。

| 機能 | 説明 |
|------|------|
| フィラー除去 | 「えー」「あのー」「まあ」等を検知し、自然な言い替えを提案 |
| 全体時間最適化 | 指定時間（例：5分）に収まるよう文字数・構成を自動調整 |
| 差分ハイライト表示 | AIの修正箇所を赤/青でハイライト（追加/削除） |
| 業界特化トーン変換 | VCモード / 稟議モード / アカデミアモード / 面接モード |
| 反復改善 | 練習するたびに原稿が磨かれる。全イテレーションを保存・比較可能 |

#### 4-2. 構造診断エンジン（Structure Diagnosis）

プレゼンの「構造」をAIが分析し、弱点を可視化する。

| チェック項目 | 内容 |
|-------------|------|
| ストーリーアーク | 導入→問題提起→解決策→根拠→CTA の流れ |
| WHYの強度 | 「なぜこれが必要なのか」が明確か |
| 問題提起の明確さ | 聴衆が課題を自分ごと化できるか |
| 根拠データの密度 | 数字・事例・権威性の裏付けがあるか |
| 競合比較の網羅性 | 差別化ポイントが伝わるか |
| 将来ビジョン | 聴衆が未来を想像できるか |

出力: ピラミッド構造の可視化図 + 改善優先順位リスト

#### 4-3. 勝率スコアエンジン（Pitch Score Engine）

**想定対象を選択:**

- VC / エンジェル投資家
- 大企業役員（稟議）
- 学会審査員
- 採用面接官

**出力:**

- 総合スコア（A〜D ランク）
- 弱点ランキング（優先改善項目）
- 改善提案

**スコア校正戦略（信頼性確保）:**

```
Phase 1: ルールベース
  → チェックリスト方式（◯項目中△項目クリア = Bランク）
  → 透明性が高く、ユーザーが「何を直せばいいか」明確

Phase 2: データドリブン
  → ユーザーが「このピッチは通った/落ちた」フィードバックを入力
  → 成功パターンのコーパスを蓄積

Phase 3: 予測モデル
  → 蓄積データでML校正 → 精度の高い確率予測
```

> 注意: 初期フェーズでは「63%の確率で通過」のような具体数値は出さない。  
> チェックリスト形式で「何ができていて何が足りないか」を明示する方が信頼を得やすい。

#### 4-4. 話し方・パフォーマンス解析

| 機能 | 説明 |
|------|------|
| 弱気ワード検出 | 「〜だと思います」「たぶん」「〜かもしれない」を検知 → 言い切り提案 |
| WPMペースグラフ | 1分あたり文字数をスライドごとにグラフ化。早口/遅すぎを指摘 |
| 熱量ヒートマップ | 声の抑揚・大きさを原稿上に色付け。棒読み箇所を可視化 |
| つまずき検知 | 言い直し・詰まりが多いスライドを自動検知 |
| メタファー自動提案 | つまずき箇所に「例えば〇〇に例えると…」という比喩を提案 |

#### 4-5. 圧迫ピッチモード（Pressure Pitch Mode）

プレゼンの **途中に** AI音声でランダムに割り込み質問を挿入する。

**割り込み例:**

- 「ちょっと待って、それって競合他社と何が違うの？」
- 「市場規模の根拠を教えて」
- 「それ、本当にユーザーが求めてるの？」

**採点項目:**

| 項目 | 内容 |
|------|------|
| 反応速度 | 割り込みへの即応力 |
| 論理維持力 | 回答の論理的整合性 |
| 再開スムーズ度 | 回答後、元のプレゼンに戻れるか |
| 感情コントロール | 動揺せず堂々と対応できたか |

#### 4-6. カメラ解析（ローカルアプリ限定・オプション）

| 機能 | 説明 |
|------|------|
| カメラ目線保持率 | 原稿ばかり見ていないか判定 |
| 原稿依存率 | 画面を見すぎていないか |
| 表情感情分類 | 緊張・自信・無表情を検知 |
| ジェスチャー解析 | 手振りが効果的に使えているか |

> ⚠️ カメラ使用は **明示的なオプトイン（同意制）** とする。デフォルトOFF。

### 🌍 Bレイヤー：英語プレゼン突破エンジン

> **実装方針**: B層は Phase 3 以降で段階的に追加する。  
> Phase 1-2 では「日本語→英語変換（テキストのみ）」に限定する。  
> 発音トレーニングは独立プロダクト級の複雑さがあるため、パートナーシップも検討する。

#### 5-1. 用途別英語変換

日本語の音声を、 **単なる翻訳ではなく文化文脈補正を含めた英語** に変換する。

| 変換モード | 特徴 |
|-----------|------|
| VC English | 投資家向け。数字と成長ストーリー重視 |
| Academic English | 学術的。根拠と方法論を明確に |
| Corporate English | ビジネスフォーマル。意思決定者向け |
| Startup Casual | カジュアル。テックコミュニティ向け |
| TED風 | ストーリーテリング重視。感情に訴える |

**翻訳品質の差別化:**

- 文化文脈補正（日本的な回りくどさを英語的な直接表現に）
- 言い切り度調整（hedging → assertive）
- 強調構造最適化（英語圏のプレゼン構成に合わせる）

#### 5-2. Speakable English モード

英語初心者が「実際に声に出せる」レベルまで原稿をブレイクダウンする。

- 文の分割（短文化）
- 呼吸ポイント表示
- 強調語ハイライト
- 発音難易度表示

#### 5-3. 発音トレーニング（Phase 4以降）

3段階の練習:

1. 単語レベル
2. 文レベル
3. 通し練習

追加機能:

- American / British 切替
- シャドーイングモード
- スピード可変再生

#### 5-4. 単語帳システム（プレゼン特化）

- ワンクリック単語登録
- 自動例文生成
- 音声再生
- 発音録音・採点
- 忘却曲線ベースの復習リマインド

#### 5-5. 崩し言い換えモード

フォーマル ⇄ カジュアルの切替:

- Very formal（外交・公式）
- Business natural（一般ビジネス）
- Startup casual（テック業界）
- Conversational（日常会話）

#### 5-6. 英語即応力トレーニング

英語での圧迫質問対応:

> "Wait, I don't understand your market size."  
> "How is this different from [competitor]?"

英語で即座に切り返す訓練。

#### 5-7. 英語文化適応解析

英語圏特有の「プレゼンの常識」との差を検出:

| 検出項目 | 説明 |
|----------|------|
| 主張の弱さ | 結論が曖昧ではないか |
| 具体性不足 | 抽象的すぎる表現 |
| 自己主張不足 | 成果のアピールが足りない |
| 回りくどさ | 日本語的な婉曲表現の残存 |

## 5. 拡張機能（ビジネススケール向け）

### 5-1. 共有と非同期フィードバック（バイラルループ強化）

練習の録画・録音データと、AIによる勝率スコア・構造診断結果をセットにして、**専用URLで他人に共有**できる。

- 共有された側（メンター・上司）はブラウザ上でタイムラインにコメント可能
- URL共有がアプリの口コミ・拡散（バイラルループ）を生み出す
- 共有範囲の制御（公開/限定公開/パスワード付き）

### 5-2. チームの「勝ちパターン」学習（Enterprise向け）

社内の「過去に通した優秀なプレゼン」のデータをアップロードすることで、**AIがその企業特有の勝ちパターンを学習**する。

- 「自社の社長が好むフォーマット」に合っているかを判定
- 企業研修での活用（新人のプレゼン力底上げ）
- 法人契約（BtoB）の単価を引き上げるキラー機能

### 5-3. 本番リアルタイムアシスト（デスクトップアプリの強み）

ZoomやTeamsでのオンライン本番プレゼン中、画面端に透明ウィジェットとして常駐。

**提供する情報（自分のパフォーマンスのみに限定）:**

| アシスト | 内容 |
|---------|------|
| ペースアラート | 「少し早口になっています」 |
| 時間リマインダー | 「残り2分です」 |
| 台本リマインダー | 原稿を半透明で表示 |
| キーメッセージ表示 | 現スライドで伝えるべき要点 |

> ⚠️ **相手の表情解析は実装しない**  
> 理由: 相手の同意なくカメラ映像を解析することはGDPR等の法規制に抵触するリスクがあり、  
> Zoom/Teams等のToS違反になる可能性がある。  
> 「自分のパフォーマンスモニタリング」に限定することで安全に提供する。

| **Smart** | 2,500〜3,000円 | Managed AI。勝率スコア、構造診断、圧迫モード、英語変換 |
| **Enterprise** | 要相談 | チーム管理、勝ちパターン学習、企業研修用、SLA付き |

**転換率を高める仕組み:**

- Free → Lite: 14日間の無料トライアル
- Lite → DIY: 「BYOK設定すれば安い」誘導
- DIY → Smart: 「構造診断で弱点が見つかりました → Smartなら自動改善」
- Smart → Enterprise: 「チームで使いませんか」案内

## 11. リスクと対策

| リスク | 影響度 | 対策 |
|--------|--------|------|
| Whisperの精度が不十分 | 中 | 複数の文字起こしエンジンを選択可能にする |
| OpenAI API の料金改定 | 中 | BYOK + ローカルLLM で依存度を下げる |
| Chrome拡張の審査不通過 | 高 | 機能を最小限に。デスクトップアプリをメインに |
| 競合の参入 | 中 | 「通す」特化のポジショニングで差別化。コミュニティ構築 |
| ユーザー定着率の低さ | 高 | 成長可視化で継続モチベーション。プリセットで体験簡素化 |
| プライバシー問題 | 高 | ローカル優先、同意制、ログ制御。法務レビュー実施 |

## 付録: 競合分析

| アプリ | カテゴリ | PreDeckとの差別化 |
|--------|---------|------------------|
| Yoodli | スピーチコーチ | PreDeckは「通す」に特化。Yoodliは話し方改善止まり |
| Poised | 会議アシスト | PreDeckは事前練習の反復に重点。Poisedはリアルタイム |
| Speeko | スピーチ練習 | PreDeckは原稿の「構造」まで踏み込む |
| DeepL / Google翻訳 | 翻訳 | PreDeckは翻訳ではなく「文化適応変換」 |
| ELSA | 発音矯正 | PreDeckはプレゼン全体の突破支援。発音は一部 |

**PreDeckの独自ポジション:**

> 「意思決定突破 × 英語適応 × 即応耐性 × 成長可視化」の統合は市場に存在しない。

# PreDeck向けローカルLLM調査レポート

作成日: 2026-05-07  
対象: PreDeck（プレデキ）の「改善AI」ローカルLLM選定  
前提用途: プレゼン原稿改善、構造診断、弱気表現検出、VC/学会/起業家向けトーン変換、想定質問生成、英語プレゼン補助、オフライン処理

---

## 1. 結論

PreDeckのローカルLLMは、**1モデルで全ユーザーに配布するのではなく、3段階構成**にするのが最適です。

| 採用区分 | 推奨モデル | 位置づけ | 理由 |
|---|---|---|---|
| 標準モデル | **Qwen3.5-9B** | 研究者・起業家の一般的なノートPC向け標準 | 9B級で高性能。日本語・英語・多言語、長文、指示追従、視覚入力に強い。Q4量子化なら16GB RAM級でも現実的。 |
| 軽量フォールバック | **Gemma 4 E4B** または **Bonsai-8B** | 低スペックPC、無料体験、短文改善 | Gemma 4 E4Bは軽量かつGoogle系で安定。Bonsai-8Bは1.15GB級で非常に軽いが、品質は標準モデルにはしない。 |
| 高品質オプション | **Gemma 4 26B-A4B** または **Qwen3.6-35B-A3B** | 上位ユーザー、MacBook Pro 32GB以上、GPU搭載PC向け | 構造診断、勝率スコア、英語文化適応、長文レビューに強い。ただし一般ノートPC標準には重い。 |
| 推論・論理補助 | **gpt-oss-20b** | 推論が必要な診断・チェックリスト補助 | OpenAIのApache 2.0オープンウェイト。16GBメモリで動作可能とされるが、英語・推論寄りで、日本語原稿改善の主役にはしない。 |
| 非推奨: 標準搭載 | **Llama 4 Scout / Maverick、Llama 3.3 70B** | 高性能だが重すぎる | 一般的な研究者・起業家のノートPC前提では実用配布に不向き。 |

**最終推奨:**

```text
Phase 1 / MVP:
  - 標準: Qwen3.5-9B Q4_K_M または MLX 4bit
  - 軽量: Gemma 4 E4B Q4 または Bonsai-8B 1bit
  - 高品質: Gemma 4 26B-A4B Q4（選択式）

Phase 2以降:
  - gpt-oss-20b を「推論診断モード」として追加
  - Qwen3.6-35B-A3B を高性能PC向け実験枠として追加
```

## 2. PreDeckで重要な評価軸

PreDeckは単なるチャットボットではなく、プレゼンを「通す」ための改善AIです。したがって、モデル選定では以下を重視します。

| 評価軸 | 重要度 | 内容 |
|---|---:|---|
| 日本語原稿改善 | 高 | 口語の自然化、フィラー除去、弱気表現の言い換え。 |
| 論理構造診断 | 高 | 問題提起、WHY、根拠、CTA、ストーリーアークを見られること。 |
| 指示追従 | 高 | 「5分に短縮」「VC向け」「差分JSONで返す」などの厳密な出力形式。 |
| 英語変換 | 中〜高 | VC English、Academic English、Speakable English。 |
| 長文コンテキスト | 中〜高 | スライド全体、文字起こし、過去イテレーションの処理。 |
| ローカル実行性 | 高 | MacBook Air/Pro、Windowsノート、研究者・起業家の手元PCで動くこと。 |
| ライセンス | 高 | 商用アプリに組み込みやすいこと。Apache 2.0 / MITが望ましい。 |
| マルチモーダル | 中 | 将来的にスライド画像、PDF、図表を直接見る場合に有利。 |

### 3.3 PreDeckでの自動選択方針

PreDeckの初期設定は、PC性能を検出して以下のように自動選択する設計が望ましいです。

| 検出条件 | 自動選択 | UI表示例 |
|---|---|---|
| RAM 8GB未満 | ローカルLLM OFF | 「このPCではローカルAIは非推奨です。API利用を推奨します。」 |
| RAM 8〜16GB、GPUなし | Gemma 4 E4B または Bonsai-8B | 「軽量モード」 |
| RAM 16GB以上、またはVRAM 8GB以上 | Qwen3.5-9B Q4 | 「標準モード」 |
| RAM 32GB以上、またはVRAM 16GB以上 | Gemma 4 26B-A4B / gpt-oss-20b選択可 | 「高品質モード」 |
| RAM 64GB以上、またはVRAM 24GB以上 | Qwen3.6-35B-A3B / Gemma 4 31B選択可 | 「上級モード」 |
| サーバー級 / 複数GPU | Llama 4系や70B超モデルを検証可 | 「Enterprise/研究室モード」 |

## 5. 企業別・シリーズ別の最新動向

### 5.1 Bonsai

Bonsai-8Bは、PrismMLの1-bitローカルLLMです。最大の価値は**性能そのものではなく、メモリ効率と配布しやすさ**です。

- 8Bモデルながら、1-bit版のモデルサイズは約1.15GB。
- Hugging Face上のモデルカードでは、EvalScope評価でAvg 70.5、MMLU-R 65.7、GSM8K 88、IFEval 79.8。
- モバイル、古いノートPC、低スペックPCに強い。
- ただし、PreDeckの「説得力ある改善AI」としては、Qwen3.5-9BやGemma 4 26B-A4Bに品質で劣る可能性が高い。

**PreDeck判断:**

```text
標準モデルではなく、軽量フォールバックに採用。
「低スペックPCでも最低限の1スライド改善ができる」体験に使う。
```

---

### 5.2 OpenAI gpt-oss-20b

OpenAIのgpt-ossは、gpt-oss-120bとgpt-oss-20bの2モデル構成です。gpt-oss-20bは21B total / 3.6B activeのMoEで、OpenAIは16GBメモリで実行可能と説明しています。

特徴:

- Apache 2.0。
- 128Kコンテキスト。
- reasoning_effortを調整可能。
- Structured Output、ツール利用、関数呼び出しとの相性が良い。
- 主にSTEM、コーディング、一般知識、英語テキスト中心の学習と説明されている。

PreDeckでは、以下に向きます。

- 勝率スコアの裏側で使う論理診断。
- VCからの圧迫質問生成。
- 「根拠が弱い」「市場規模の説明が不足」などのチェックリスト評価。
- ただし、日本語の話し言葉改善、自然な原稿彫刻ではQwen系を優先。

**PreDeck判断:**

```text
標準原稿改善モデルではなく、推論診断サブモデルとして採用候補。
```

---

### 5.3 Qwenシリーズ / Alibaba

Qwenは、PreDeckに最も相性が良いシリーズです。理由は、**日本語を含む多言語、長文、指示追従、視覚理解、エージェント性能**のバランスが高いためです。

注目モデル:

| モデル | 用途 | PreDeck評価 |
|---|---|---|
| Qwen3.5-9B | 標準ローカル改善AI | **最有力** |
| Qwen3.5-4B | 軽量版 | Gemma/Bonsaiと比較対象 |
| Qwen3.6-35B-A3B | 高度診断・上位PC向け | 高品質オプション |
| Qwen3-30B-A3B / Qwen3-14B | 旧世代安定候補 | 3.5以降が使えるなら優先度は下がる |

Qwen3.5-9Bは、モデルカード上で9B、262Kネイティブコンテキスト、最大1.01M拡張、201言語対応、Vision Encoder付きと説明されています。ベンチマークではMMLU-Pro 82.5、GPQA Diamond 81.7、IFEval 91.5、AA-LCR 63.0、MMMU-Pro 70.1が示されています。

**PreDeck判断:**

```text
Qwen3.5-9Bを標準モデルにする。
英語プレゼン、VCピッチ、研究発表、スライド画像理解まで拡張しやすい。
```

---

### 5.4 Gemmaシリーズ / Google DeepMind

Gemma 4は、Google DeepMindの最新オープンモデルファミリーです。E2B、E4B、26B-A4B、31Bの4サイズ構成で、Apache 2.0、128K〜256Kコンテキスト、マルチモーダル対応が特徴です。

注目点:

- E2B/E4Bは音声入力も対応。
- 26B-A4Bは25.2B total / 3.8B activeのMoEで、実行効率が良い。
- 31BはDenseで最高品質だが重い。

PreDeckでは以下の使い分けが妥当です。

| モデル | 用途 | 判断 |
|---|---|---|
| Gemma 4 E4B | 軽量モード | 有力。低スペック救済に使いやすい。 |
| Gemma 4 26B-A4B | 高品質モード | 有力。32GB RAM以上向け。 |
| Gemma 4 31B | 最高品質モード | 高品質だが標準搭載には重い。 |

**PreDeck判断:**

```text
Gemma 4 E4Bを軽量モード、Gemma 4 26B-A4Bを高品質モードにする。
標準モデルはQwen3.5-9Bを優先。
```

---

### 5.5 Microsoft Phiシリーズ

Phiシリーズは、小型・高品質な推論モデルとして有力です。ただし、Phi-4は主に英語・理数・コード寄りです。

- Phi-4: 14B、MIT、16K context。MMLU 84.8、GPQA 56.1、MATH 80.4、HumanEval 82.6。
- Phi-4-mini-reasoning: 3.8B、128K context、数学推論特化。AIME 57.5、MATH-500 94.6、GPQA 52.0。

**PreDeck判断:**

```text
研究者向けの数理・論理説明補助には良い。
ただし日本語原稿改善、VCピッチ、英語文化適応ではQwen/Gemmaを優先。
```

### 5.6 Meta Llamaシリーズ

Llama 4はScoutとMaverickが中心です。Llama 4 Scoutは109B total / 17B active、10Mコンテキスト。Maverickは400B total / 17B active、1Mコンテキストです。

性能は高いものの、PreDeckの対象である「研究者・起業家が持つ一般的なノートPC」には重すぎます。

注意点:

- Llama 4はApache 2.0ではなく、Llama 4 Community License。
- Scoutは10Mコンテキストが強いが、総パラメータ109B級でローカル配布には重い。
- Maverickは事実上サーバー向け。
- Llama 4のLMArena評価では、公開版と評価版の差異が報道され、ベンチマーク透明性に注意が必要。

**PreDeck判断:**

```text
標準搭載しない。
Enterpriseサーバー版や研究用途でのみ検討。
```

### 5.7 Mistral

Mistral Small 3.2 24Bは、Apache 2.0、128Kコンテキスト、指示追従・関数呼び出しの改善が特徴です。

公式モデルカードでは以下が示されています。

- Wildbench v2: 65.33%
- Arena Hard v2: 43.1%
- MMLU-Pro: 69.06%
- GPQA Diamond: 46.13%
- HumanEval Plus: 92.90%
- BF16/FP16で約55GB GPU RAMが必要

**PreDeck判断:**

```text
英語・欧州言語・関数呼び出しには有力。
日本語中心のPreDeck標準ではQwen/Gemma優先。
```

### 5.8 DeepSeek

DeepSeek-R1-Distill-Qwen-14B / 32Bは推論モデルとして有力です。MITライセンスで、OllamaやGGUFでも利用しやすいです。

ただし、R1系は長い思考出力、冗長な回答、言語混在が出やすく、PreDeckの「自然で短く、話せる原稿」には必ずしも合いません。

**PreDeck判断:**

```text
想定質問生成、反論生成、論理チェックには使える。
原稿改善の標準モデルにはしない。
```

## 7. 実装方針

### 7.1 Ollama / llama.cpp / MLXの3系統を想定

| 実行環境 | 推奨 |
|---|---|
| Windows + NVIDIA GPU | Ollama / LM Studio / llama.cpp CUDA |
| Mac Apple Silicon | MLX / Ollama / llama.cpp Metal |
| CPU中心 | llama.cpp GGUF。Qwen3.5-9Bは重いのでBonsaiまたはGemma E4B推奨 |
| 将来のサーバー版 | vLLM / SGLang |

### 7.2 コンテキスト設計

長文コンテキストを持つモデルでも、PreDeckではフルコンテキストを毎回使うべきではありません。

推奨入力設計:

```text
現在スライド原稿: 詳細入力
前後スライド: 要約入力
全体構成: JSON要約
過去イテレーション: 弱点・スコア履歴のみ
録音文字起こし: 現在セッション部分のみ
```

理由:

- 262Kや1Mコンテキストを使うと、KVキャッシュでメモリを消費する。
- 一般ユーザーPCでは8K〜32Kに抑えた方が安定する。
- PreDeckでは「全量投入」より「スライド単位 + 全体要約」の方がUXが良い。

### 7.3 出力形式

LLM出力は自由文ではなく、JSON Schemaに寄せるべきです。

```json
{
  "improved_script": "...",
  "changes": [
    {"type": "delete_filler", "before": "えー", "after": ""},
    {"type": "strengthen_claim", "before": "だと思います", "after": "です"}
  ],
  "structure_diagnosis": {
    "problem_clarity": 4,
    "why_strength": 3,
    "evidence_density": 2,
    "cta_clarity": 3
  },
  "priority_actions": ["市場規模の根拠を1つ追加", "冒頭で結論を先に述べる"]
}
```

### 9.1 モデル選択UI

```text
AIモデル設定

[自動選択 推奨]
  PC性能を見て自動で選びます

[軽量]
  Gemma 4 E4B / Bonsai-8B

[高品質]
  Gemma 4 26B-A4B
  高性能PC向け。スライド全体診断に最適。

[推論診断]
  gpt-oss-20b
  圧迫質問、論理チェック、想定反論生成に使用。
```

### 9.2 自動選択ロジック

PCクラス判定は、RAM / VRAM / Unified Memory / 空きストレージを見て行います。重要なのは、モデル本体だけでなく、Whisper、PDF画像化、セッション保存、KVキャッシュも同時に動く点です。

| PCクラス | 判定条件 | 自動選択 | 代替候補 | 注意 |
|---|---|---|---|---|
| **S0** | RAM 8GB未満、空き容量10GB未満 | ローカルLLM OFF | BYOK / Managed AI | ローカルLLMを有効化しない方がUXが良い |
| **S1** | RAM 8〜16GB、GPUなし〜VRAM 6GB | Gemma 4 E4B | Bonsai-8B、Phi-4-mini-reasoning | コンテキストは4K〜8K中心。全スライド一括診断は避ける |
| **S2** | RAM 16〜32GB、またはVRAM 8〜12GB | Qwen3.5-9B | Phi-4 14B、DeepSeek 14B | PreDeck標準。8K〜16K中心、必要時32K |
| **S3** | RAM 32〜64GB、またはVRAM 16GB前後 | Gemma 4 26B-A4B | gpt-oss-20b、Mistral Small 3.2 | 高品質モード。長文時は速度低下に注意 |
| **S4** | RAM 64GB以上、またはVRAM 24GB以上 | Qwen3.6-35B-A3B | Gemma 4 31B | 上級モード。32K以上の長文診断が現実的 |
| **S5** | 128GB RAM以上、48GB VRAM以上、複数GPU等 | 70B超 / Llama 4系 | Enterpriseサーバー用モデル | ノートPC向けPreDeckとは別枠 |

実装では、初回起動時に以下のような選択を出すとよいです。

```text
このPCでは「標準モード: Qwen3.5-9B」が推奨です。
より高速に動かす場合は「軽量モード: Gemma 4 E4B」を選択できます。
より高品質な診断を行うには、32GB以上のメモリまたは16GB以上のVRAMが必要です。
```

## 12. 最終提案

PreDeckの改善AIは、以下の設計で進めるべきです。

```text
1. **S2標準ノートPC**をPreDeckの基準スペックにし、Qwen3.5-9Bを標準モデルにする
2. **S1軽量モバイルPC**向けに、Gemma 4 E4Bを軽量モデルにする
3. **S1下限環境**向けに、Bonsai-8Bを超軽量フォールバックにする
4. **S3 ProノートPC**向けに、Gemma 4 26B-A4Bを高品質モードにする
5. **S3以上**で、gpt-oss-20bを推論診断・圧迫質問モードに追加する
6. **S4以上**で、Qwen3.6-35B-A3B / Gemma 4 31Bを上級モードとして選択可能にする
7. Llama 4系は標準搭載せず、**S5 Enterpriseサーバー用途**でのみ検討する
```

この構成が、**性能、ローカル実行性、商用ライセンス、ユーザーPC適合性、PreDeckのプロダクト価値**のバランスが最も良いです。

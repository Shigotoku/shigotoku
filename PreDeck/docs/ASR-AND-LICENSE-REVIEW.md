# 文字起こし方式の比較とライセンス確認

作成日: 2026-11-12 / 区分: 社内検討資料（法的助言ではありません。売却前に弁護士の確認を受けてください）

## 1. 文字起こし方式の比較

評価軸: 利用者の使いやすさ / 当社コスト / 専門用語への強さ / 秘匿性 / 売却時の説明のしやすさ

| 方式 | 利用者の手間 | 当社コスト | 精度・専門用語 | 秘匿性 | 弱点 |
|---|---|---|---|---|---|
| **A. Chrome 端末内認識（ちょこっと方式）** | 低（初回に音声パックの導入のみ） | **ゼロ** | 一般語は良好。専門語は辞書で補強（補正＋バイアス） | **高（音声が端末外に出ない）** | Chrome 前提。Chrome の仕様変更に依存。句読点は自前整形 |
| B. ブラウザ内 Whisper（WebGPU/WASM） | 中（数百 MB のモデル DL、端末の性能依存） | ゼロ | 高い（一般語・専門語とも） | 高 | 低スペック端末で遅い。実装・保守が重い |
| C. サーバー Whisper | 低 | **高（GPU 常時）** | 高い | 低（音声を送る） | コスト・秘匿性の両面で不利 |
| D. クラウド STT（Google 等） | 低 | 従量（分あたり課金） | 高い。専門語の語彙登録あり | 低（音声を送る） | 従量コストが利用に比例 |

### 結論（意見）
**A を標準にし、B を将来の任意オプション（高精度モード）に、C・D は採用しない**のが良いと考えます。

- 「当社のコストを最小に」「利用者に使いやすく」「資料や音声を外に出したくない」の 3 点を同時に満たせるのは A だけです。
- A の弱点（専門語）は、辞書（標準＋マイ辞書）と、AI 添削でテキストを直す工程で補えます。AI に送るのはテキストだけなので、秘匿性の説明も一貫します。
- ただし A は **Chrome 依存**です。リスクは次のとおりです。
  - Chrome が機能を変更・廃止すると影響を受ける（実際に引き継ぎ資料にもバージョン差の対策が多数ある）。
  - 買い手から見ると「他社ブラウザ機能への依存」が事業リスクになる。
  - 対策: 認識部分を `AsrEngine` として抽象化し、B（Whisper Web）に差し替え可能にしておく（次の作業候補）。
- ローカル Whisper（旧 PreDeck の方式）は、配布・インストールの手間が利用者の使いやすさを損ない、Web 版の方針と合わないため見送ります。

## 2. ライセンス確認

### 2.1 取り込んだ「ちょこっとワークス」由来コード（要対応）
- 対象: `app/src/lib/speech/` の `speechRecognition.ts`、`speechTextFormat.ts`、`medicalTermPostProcess.ts`、`punctInfer.ts`、`rephrase.ts`、`vocabulary/` の一部（`format.ts`、`asr/`、科学・医療の新規辞書は PreDeck で新規作成）。
- 元の表示: `UNLICENSED`・`private`、著作者 **Meditoku Inc.（メディトク）**。
- 前提（2026-11-12 確認）: **メディトクは親会社になる予定**で、シゴトクはその子会社という位置づけ。
- 親子会社でも、**法人が別なら著作権は別**です。「同じグループだから自由に使える」とは法的には言えません。売却時の確認で必ず見られます。
- 売却の形によって、必要な整理が変わります。

| 売り方 | リスク | 必要な整理 |
|---|---|---|
| シゴトク（子会社）の株式を売る | コードの権利が親会社にあると、**買い手は使用権のない会社を買う**ことになる | コード（`speech/`）の**著作権をシゴトクへ譲渡**するか、**永続・譲渡可・再許諾可の許諾**をシゴトクへ付与する |
| PreDeck だけを事業譲渡する | 許諾が譲渡不可・グループ内限定だと、譲渡先が使えない | 許諾に**承継（譲渡）可**を明記する |
| 親会社ごと売る | 親子とも売るので問題は小さい | 権利が親会社にあることを資産として整理 |

- 推奨: **メディトクからシゴトクへ、`speech-common` 由来部分の著作権譲渡（または独占的・永続・譲渡可の許諾）を書面で行う。** 対価は無償でも、書面と社内承認（取締役会など）を残す。利益相反や移転価格の観点で税務上の確認も必要です。
- 逆に、権利を親会社に残す場合は、シゴトクが売却されると許諾が失効する条項になっていないか確認する。
- 許諾が得られない場合の逃げ道: `speech/` は Web Speech API の公開仕様に沿った薄いラッパーなので、書き直しは現実的（`asr/` で差し替え可能な構造にしてあるため影響範囲は小さい）。
- 暫定措置: 契約が済むまで公開・販売はしない。コード先頭に出所（ちょこっとワークス / Meditoku Inc.）を明記した NOTICE を置く（次の作業）。
### 2.2 取り込まなかったデータ（参考）
- 薬剤名辞書: 出典は厚生労働省「薬価基準収載品目リスト」。国の公開データだが、利用条件（政府標準利用規約・出典表示）の確認が必要。
- 病名辞書: 出典は MEDIS-DC「ICD10 対応標準病名マスター」。**配布元の利用規約に再配布条件がある可能性があり**、取り込む場合は必ず規約を確認する。

### 2.4 旧ローカル版（`legacy/`）の依存（Web 版へ移行後は不要）
- `PyMuPDF` は **AGPL-3.0**（または商用ライセンス）。配布・サービス提供の形によってはソース開示義務が生じるため、**Web 版・売却対象には含めない**。
- `openai-whisper`・`faster-whisper` は MIT 系だが、モデル重みの利用条件は別途確認が必要。
- 売却対象は `app/` `api/` `landing-page/` とし、`legacy/` は売却前に削除する。

### 2.5 外部サービス
- Chrome の Web Speech API: 端末内モードのみ使用し、音声は Google に送らない設計（`privacyMode: clinical`）。クラウドモードは使わない。
- Gemini API: テキストのみ送信。無料枠・有料枠で学習利用の扱いが異なるため、**有料（学習に使われない）設定**を使うこと。BYOK の場合も同様に利用者側の契約に従う。
- PreDeck のプライバシーポリシーに「音声・スライドは端末外に出ない／テキストのみ AI 事業者へ送信」を明記する。
